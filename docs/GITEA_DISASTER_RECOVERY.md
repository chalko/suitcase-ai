# Gitea Disaster Recovery & Restoration Runbook

This document defines the sovereign backup architecture, Grandfather-Father-Son (GFS) retention doctrine, step-by-step disaster recovery runbook, and live audit certification record for the Camp Colt Gitea service.

---

## 1. Sovereign 3-2-1 Backup Architecture

Camp Colt implements a strict **3-2-1 backup doctrine** to guarantee zero data loss and sovereign survivability of all Git repositories, issues, user keys, and CI/CD states:

1. **3 Copies of Data:**

   - **Primary Live Data:** Running Gitea instance persistent volume (`gitea-data` PVC mounted at `/data`).
   - **Local Atomic Snapshot:** Daily scratch dump generated by `gitea dump` at `/backup/gitea-dump-<TIMESTAMP>.zip`.
   - **Off-site Sovereign Cloud Archive:** Encrypted synchronization to Google Drive storage tier (`gdrive:daily/`, `weekly/`, `monthly/`, `yearly/`).

2. **2 Different Media Formats:**

   - Local NVMe / Enterprise SSD block storage on Talos Linux Kubernetes hypervisors.
   - Remote Google Workspace Shared Drive cloud object storage (`folder_id: 1UwUvqwyIFOlHJ8W8EtaHFKpR4RvkZALF`).

3. **1 Immutable Off-site Copy:**
   - Dedicated Google Service Account authentication (`gitea-gdrive-backup-secret` containing `sa.json`) replicating dumps outside the local hypervisor fault domain.


## 2. GFS Retention & Scheduling Policy

The automated CronJob (`provision/k8s/gitea/backup-cronjob.yaml`) runs daily at **03:00 UTC** and executes:

| Tier        | Schedule                        | Retention Period     | Pruning Mechanism              |
| :---------- | :------------------------------ | :------------------- | :----------------------------- |
| **Daily**   | Daily @ 03:00 UTC               | 14 Days              | `rclone delete --min-age 14d`  |
| **Weekly**  | Every Sunday (`date +%u == 7`)  | 6 Weeks (42 Days)    | `rclone delete --min-age 42d`  |
| **Monthly** | 1st of Month (`date +%d == 01`) | 13 Months (395 Days) | `rclone delete --min-age 395d` |
| **Yearly**  | 1st of Year (`date +%j == 001`) | **Permanent**        | No deletion rule               |

Each archive is paired with an SHA256 checksum file (`.zip.sha256`) generated immediately after atomic snapshot completion.

## 3. Disaster Recovery & Restoration Procedures

### Scenario A: Complete Cluster Rebuild (Cold Recovery)

In the event of complete hypervisor loss or cluster destruction:

#### Step 1: Pre-requisites & Environment Setup

Ensure Colt environment and credentials are loaded:

```bash
source scripts/load_colt_env.sh
./scripts/verify-colt-context.sh
```

Ensure the Gitea namespace and Google Drive secret exist:

```bash
kubectl apply -f provision/k8s/gitea/namespace.yaml
# Ensure gitea-gdrive-backup-secret is populated via Vault / SealedSecrets
```

#### Step 2: Download & Validate the Latest Backup Archive

Run an ephemeral restoration container or retrieve via `rclone`:

```bash
export RCLONE_CONFIG_GDRIVE_TYPE="drive"
export RCLONE_CONFIG_GDRIVE_SCOPE="drive"
export RCLONE_CONFIG_GDRIVE_SERVICE_ACCOUNT_FILE="/path/to/sa.json"
export RCLONE_CONFIG_GDRIVE_ROOT_FOLDER_ID="1UwUvqwyIFOlHJ8W8EtaHFKpR4RvkZALF"

# List available dumps
rclone lsl gdrive:daily/

# Download latest dump and checksum
LATEST_ZIP=$(rclone lsf gdrive:daily/ --include "gitea-dump-*.zip" | sort -r | head -n1)
rclone copy "gdrive:daily/${LATEST_ZIP}" ./restore/
rclone copy "gdrive:daily/${LATEST_ZIP}.sha256" ./restore/

# Verify cryptographic checksum
cd ./restore
sha256sum -c "${LATEST_ZIP}.sha256"
```

#### Step 3: Unpack Archive and Restore Data

1. Unzip the archive:

   ```bash
   unzip "${LATEST_ZIP}" -d /tmp/gitea-unpacked
   ```

2. Scale down Gitea deployment:

   ```bash
   kubectl scale deployment gitea --replicas=0 -n gitea
   ```

3. Copy data to PVC (`gitea-data`):

   - Place `app.ini` into `/data/gitea/conf/app.ini`.
   - Restore bare Git repositories into `/data/git/repositories/`.
   - If SQLite: copy `gitea-db.sql` or SQLite DB into `/data/gitea/gitea.db`.
   - Restore `data/` directory (avatars, attachments, LFS objects).

4. Correct ownership:

   ```bash
   chown -R 1000:1000 /data
   ```

5. Scale Gitea deployment back up:

   ```bash
   kubectl scale deployment gitea --replicas=1 -n gitea
   ```
